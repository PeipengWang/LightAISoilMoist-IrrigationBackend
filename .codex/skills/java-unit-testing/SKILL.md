# 测试规范

测试要帮助后续改代码时快速发现问题。优先写可自动、独立、可重复的测试；真实设备和真实 OneNET 调用应作为集成/联调测试隔离。

## 测试分类

- 单元测试：不依赖网络、真实设备、真实文件系统状态或手工数据库数据。使用 mock、内存对象或测试数据库。
- 集成测试：可以启动 Spring 上下文、访问 H2、验证 Repository/Service 协作。
- 联调测试：调用 OneNET、MQTT、真实设备、水泵等外部资源。必须显式命名或打 tag，避免默认 `mvn test` 自动执行。

## 单元测试要求

- 测试放在 `src/test/java`，包名与被测类一致。
- 使用断言验证行为，不用 `System.out` 让人肉判断。
- 每个测试独立准备数据，不依赖执行顺序。
- 覆盖正常路径、边界值和错误输入。
- 修改核心业务、阈值计算、命令校验、上传安全、异常转换时应补测试。

## 外部平台测试

- 不在测试类中硬编码真实 accessKey、token、设备密钥。
- 真实网络测试默认禁用，可用 JUnit tag、profile 或环境变量显式开启。
- HTTP/MQTT 客户端逻辑优先通过 mock server、接口抽象或可替换 client 测试。
- 联调测试可以保留必要日志，但不要作为单元测试规范样板。

## 数据库测试

- Repository/Service 集成测试使用测试数据自动准备和清理。
- 不假设本地 `data/threshold_db` 已存在某条人工数据。
- 涉及写库的测试使用事务回滚或独立测试库。

## 提交前验证

- 普通后端改动至少运行相关单元测试。
- 影响 Spring 配置、Repository、启动流程时运行 `mvn test`。
- 如果测试因外部环境不可运行，要说明原因，并尽量提供可自动化的替代验证。
