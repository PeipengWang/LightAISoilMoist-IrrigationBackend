# 安全规范

本项目涉及设备密钥、OneNET/MQTT 调用、文件上传和本地数据库。安全要求优先落在这些真实风险上。

## 密钥和配置

- 不在 Java 代码、测试代码、README 或示例请求中硬编码真实 `accessKey`、token、密码、Authorization header。
- 密钥通过环境变量、外部配置或本地不入库配置注入。提交的 `application.yml` 只能包含占位符或非敏感默认值。
- 日志和错误响应中必须脱敏密钥、token、签名串和完整 Authorization header。
- H2 console、Swagger/Knife4j、调试端口只适合开发环境；生产配置必须关闭或加访问控制。

## 输入校验

- 所有对外接口都要校验用户输入。新增接口优先使用 DTO + Bean Validation。
- 页大小、时间范围、设备名、属性标识、阈值、上传备注等都要设定合理边界。
- 不信任前端传入的设备名、属性标识、文件名、contentType、分页参数。
- 对外重定向、文件路径、URL 参数如后续出现，必须做白名单或规范化校验。

## 文件上传

- 上传文件必须限制大小、类型和扩展名。
- 不能只相信 `MultipartFile.getContentType()`；应结合扩展名白名单和文件内容校验。
- 生成服务端文件名，禁止使用用户原始文件名作为存储名。
- 解析或返回文件路径前使用 `normalize`，确保最终路径仍在上传根目录下。
- 返回文件时使用服务端保存的 contentType 和文件名，避免响应头注入。

## 外部平台和网络调用

- HTTP/MQTT 调用必须设置超时。
- 第三方错误不要把原始敏感响应透传给前端。
- 命令下发类接口属于敏感操作，应校验属性是否可写、值类型和值范围，并记录决策日志。
- 后续如加入登录或多用户，所有个人/设备/图片/配置资源必须做权限校验。

## 数据与日志

- 避免在日志中记录完整请求体，尤其是包含 token、文件信息、用户输入的大字段。
- 数据库配置、上传根目录、外部服务地址应按环境区分。
- 生产环境不要启用 `ddl-auto: update` 作为长期方案；重要表结构变化应有迁移脚本或明确升级步骤。
