# 智慧种植平台 · 服务端方案文档

> 文档版本：v1.0 ｜ 适用范围：基于 STM32 土壤采集端 + 中国移动 OneNET 云平台 + Spring Boot 服务端的智慧农业一体化系统

---

## 1. 文档说明

本文档以\*\*服务端（Spring Boot 后端）\*\*为核心视角，结合《采集端方案》所描述的 STM32 土壤质量检测终端，对整套"硬件采集 + 云端传输 + 可视化监测 + 智能分析 + 自主决策控制"一体化系统的技术架构做整体介绍，供评审、开发与部署人员快速建立全局认知。

- **服务端定位**：位于"OneNET 云平台"与"前端/移动端"之间，承担**数据汇聚、协议转换、指令编排、阈值与物候管理、决策数据支撑、统一 API 供给**的中枢职责。
- **阅读导航**：第 3~~4 章为整体架构与采集端概述（背景）；第 5 章为服务端技术架构（核心）；第 6~~9 章为对接、数据流、安全与演进。

## 2. 项目背景与定位

传统农业普遍存在"土壤数据靠经验、环境监测不及时、水肥管控不精准、种植决策无依据"的痛点。本项目以果园（如苹果等经济作物）为落地场景，构建一体化智慧种植管理系统：

| 能力层    | 职责                    | 对应模块                  |
| ------ | --------------------- | --------------------- |
| 硬件采集   | 全天候采集土壤/环境多源数据        | STM32 采集端（见第 4 章）     |
| 云端传输   | 4G 无线上云、多设备接入         | 中国移动 OneNET 物联网平台     |
| 可视化监测  | 实时看板、历史回溯、趋势分析        | Vue3 前端 / 移动端（见第 6 章） |
| 智能分析   | 分周期阈值 + 气象融合 + LLM 决策 | 服务端决策模块（见 5.10）       |
| 自主决策控制 | 灌溉闭环、阈值下发、人工干预        | 服务端指令下发（见 5.8）        |

服务端是上述能力的"承上启下"层：**向上**以统一 REST/SSE 接口供给前端，**向下**通过 OneNET 北向 API 拉取设备最新/历史数据、并向设备下发控制指令。

## 3. 整体技术架构

### 3.1 分层架构

```
┌──────────────────────────────────────────────────────────────────┐
│                          应用层（前端 / 移动端）                       │
│   Vue3 + TypeScript + Pinia + Element Plus + Chart.js              │
│   实时监测 · 历史回溯 · 智能决策 · 阈值配置 · 📱 响应式移动适配          │
└───────────────────────────┬──────────────────────────────────────┘
                             │  REST / SSE  (BASE=/api, 端口 8086)
┌───────────────────────────▼──────────────────────────────────────┐
│                        服务端（Spring Boot）                        │
│  Controller  │  Service  │  Config  │  Model/JPA  │  Repository    │
│  · 设备数据聚合  · 指令编排  · 阈值/物候管理  · 决策数据支撑  · 日志留存   │
└───────────────────────────┬──────────────────────────────────────┘
                             │  OneNET 北向 REST API（HMAC-SHA256 鉴权）
                             │  query-device-property / history / set-desired-property
┌───────────────────────────▼──────────────────────────────────────┐
│                     中国移动 OneNET 云平台                          │
│   设备影子 / 属性存储 / 命令下发通道（MQTT $sys/.../property/set）     │
└───────────────────────────┬──────────────────────────────────────┘
                             │  4G + MQTT（AT 指令状态机，非阻塞）
┌───────────────────────────▼──────────────────────────────────────┐
│                      感知层（STM32 采集端）                         │
│  STM32F103 + 土壤PH/湿度/温湿度/光照/NPK 传感器 + 继电器(水泵)        │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 数据流概要

1. **上行（采集→云端→服务端→前端）**：STM32 每秒采样、每 20s 经 4G/MQTT 上报属性至 OneNET；服务端以 REST 轮询兜底（2s 间隔）回填内存缓存；前端经 SSE（2s 推送、变化才推）+ 10s 兜底轮询获取实时数据。
2. **下行（前端→服务端→云端→设备）**：前端/阈值触发控制 → 服务端 `POST /api/command` → OneNET `set-desired-property` → STM32 继电器动作（水泵/阈值）。
3. **闭环**：设备状态（F）回采至服务端，前端实时呈现，形成"感知—决策—执行—反馈"灌溉控制闭环。

## 4. 采集端概述（源自《采集端方案》）

> 本节摘录采集端关键技术要点，用于明确服务端的数据来源与控制目标。

### 4.1 硬件与采集能力

| 类别   | 设备                   | 接口                    | 说明            |
| ---- | -------------------- | --------------------- | ------------- |
| 主控   | STM32F103（Cortex-M3） | —                     | 嵌入式主逻辑、4G 状态机 |
| 土壤   | 土壤 PH 传感器            | ADC (PA4)             | 公式换算 0~14     |
| 土壤   | 土壤湿度传感器              | ADC (PA5)             | 百分比 0~100%    |
| 环境   | DHT11 温湿度            | 单总线 (PB5)             | 环境温度/湿度       |
| 环境   | BH1750 光照            | I2C (PB6/7)           | 光照强度 Lux      |
| 土壤养分 | NPK 氮磷钾              | RS485 Modbus (USART1) | N/P/K (mg/kg) |
| 执行器  | 继电器（水泵）              | GPIO (PB3)            | 灌溉控制          |
| 告警   | 蜂鸣器                  | GPIO (PC13)           | PH/湿度异常报警     |

### 4.2 云端通信与数据属性

- 通信方式：4G 模块驱动 + **MQTT** 对接 OneNET；支持 TLS/SSL 与 HMAC 设备认证。
- 上报主题：`$sys/{ProductID}/{DeviceName}/thing/property/post`
- 控制（下发）主题：`$sys/{ProductID}/{DeviceName}/thing/property/set`

**属性标识（服务端据此读写，关键字段）：**

| 标识            | 含义                  | 服务端用途              |
| ------------- | ------------------- | ------------------ |
| A             | 土壤 PH 值             | 实时监测               |
| B             | 土壤湿度                | 实时监测 / 灌溉判据        |
| C / D         | 环境温度 / 湿度           | 实时监测               |
| E             | 光照强度                | 实时监测               |
| **F**         | **继电器（水泵）状态**       | **指令下发：0=关 / 1=开** |
| G / H         | PH 报警 / 湿度报警标志      | 状态呈现               |
| **I / J**     | **PH 下限 / 上限阈值**    | **阈值下发**           |
| **K / L**     | **土壤湿度下限 / 上限阈值**   | **阈值下发**           |
| **M / N / O** | **氮 N / 磷 P / 钾 K** | **养分监测**           |

### 4.3 本地逻辑（设备侧）

- 报警与自动灌溉：`checkAlarmAndControl()` 依据阈值控制继电器，并采用双标志位**防抖**，避免水泵频繁启停。
- 阈值可由本地按键设置，亦可经 OneNET 远程下发（I/J/K/L/F）。

### 5.1 技术选型

### 5.2 部署与运行

### 5.4 与 OneNET 云平台对接

- **Base URL**：`https://iot-api.heclouds.com`（中国移动 OneNET 北向 API）。
- **鉴权**：`OneNetApiClient.generateApiToken()` 采用 **HMAC-SHA256**，`version=2022-05-01`，按 `products/{pid}/devices/{name}` 签名写入 `Authorization` 头。
- **核心 API**：
  - `query-device-property`：查询设备最新属性（实时数据兜底）。
  - `query-device-property-history`：查询单属性历史（趋势分析）。
  - `set-device-desired-property`：下发期望值（控制指令）。
- **凭证（DeviceConfig，硬编码）**：农业主设备 `device`，产品 `FeGVC46Lne`；另含 `DHT11` 设备（产品 `09B8L0Ji9W`）。MQTT 服务器 `183.230.40.96:1883`。
- **数据获取策略（重要）**：代码设计了 Paho **MQTT 订阅**通道，但 `afterPropertiesSet` 中 `startDevice()` 实际被注释，故当前**实时数据依赖 REST 轮询兜底**——内存 `ConcurrentHashMap` 缓存 + 每设备读写锁，`needsRefresh`（2s 间隔）触发 `refreshFromApi()` 从 OneNET 回填。该设计保证在无公网 MQTT 环境下仍可运行。

### 5.5 数据模型（JPA 实体）

> 这些实体支撑"**分周期本地化��值**"与"**农事操作全程留痕**"两大产品特性。

### 5.6 REST API 清单（面向前端）

统一响应：`Result<T>`（`code` / `message` / `data`）。

| 方法     | 路径                                   | 说明                                              |
| ------ | ------------------------------------ | ----------------------------------------------- |
| GET    | `/api/devices`                       | 设备列表及属性元数据                                      |
| GET    | `/api/latest`                        | 实时缓存数据（可带 `device_name`）                        |
| GET    | `/api/latest/api`                    | 走 OneNET REST 兜底查最新值                            |
| GET    | `/api/history`                       | 单属性历史（`device_name/identifier/start/end/limit`） |
| GET    | `/api/history/all`                   | 全部属性历史                                          |
| GET    | `/api/stream`                        | **SSE 实时推送**（2s 轮询缓存，变化才推）                      |
| POST   | `/api/command`                       | **指令下发** `{device_name, identifier, value}`     |
| GET    | `/api/decision-logs`                 | 控制/决策日志分页查询                                     |
| GET    | `/api/thresholds/current`            | 当前生效阈值                                          |
| GET    | `/api/thresholds/stages`             | 物候阶段列表                                          |
| GET    | `/api/thresholds/stages/{id}`        | 阶段阈值详情                                          |
| PUT    | `/api/thresholds/{id}`               | 更新阶段阈值                                          |
| GET    | `/api/thresholds/{id}/history`       | 阈值变更历史                                          |
| POST   | `/api/thresholds/phenology/override` | 物候阈值覆盖（个性化）                                     |
| DELETE | `/api/thresholds/phenology/override` | 取消覆盖                                            |

### 5.7 实时数据推送（SSE）

- 服务端 `GET /api/stream`：每 2s 检查缓存，仅当数据变化时才向客户端推送，降低带宽与前端重绘。
- 前端 `stores/devices.ts`：`createSSEConnection('/api/stream')` 接收推送，断线指数退避重连；并以 `setInterval(refreshLatest, 10000)` 作**兜底轮询**，保证弱网下不丢数据。

### 5.8 指令下发与控制闭环

- 入口：`POST /api/command`，请求体 `{device_name, identifier, value}`，服务端校验读写属性后调用 `setDesiredProperty` 下发至 OneNET。
- **字段映射（与采集端一致）**：
  | identifier      | 含义          | 取值            |
  | --------------- | ----------- | ------------- |
  | `F`             | 水泵继电器       | `0`=关 / `1`=开 |
  | `I` / `J`       | PH 下限 / 上限  | 阈值            |
  | `K` / `L`       | 土壤湿度下限 / 上限 | 阈值            |
  | `M` / `N` / `O` | 氮 / 磷 / 钾   | 养分值           |
- **闭环链路**：前端开关/阈值触发 → `POST /api/command` → OneNET `set-desired-property` → STM32 继电器动作 → 设备状态 F 回采 → 前端实时呈现。
- **可观测性**：每次写操作均记录 `DecisionLog`（含设备/标识/取值/决策类型/成败），满足"操作可追溯"。

### 5.9 阈值与物候管理（分周期本地化阈值）

- 由 `ThresholdController` + `ThresholdService` + `PhenologyService` 实现。
- 物候阶段（萌芽/开花/结果/膨大/休眠）各自关联 `StageThreshold`，解决"通用农业系统适配性差"的短板。
- 支持 `phenology/override` 覆盖，适配不同地块、树龄的个性化种植需求。

### 5.10 智能决策模块（服务端封装 LLM/智能体）

服务端为前端智能决策能力提供**数据底座与接口契约**：

- **数据输入**：实时数据（OneNET）+ 历史数据（趋势）+ 物候阶段阈值（`StageThreshold`）+ 外部气象（降雨预报）。
- **接口契约（前端消费）**：
  - `POST /api/decision/summary`：输出结构化种植评估报告与农事建议（如"湿度过高+预报降雨→预警积水烂根""膨大期养分不足→推送补肥方案"）。
  - `POST /api/chat/stream`：流式对话助手（"小沂"），SSE 返回 `chunk/done/tts_text`。
- **可追溯**：决策结果、人工干预、参数修改均落 `DecisionLog`，自动生成完整决策日志。
- **实现说明**：服务端聚合上述多源数据并提供决策/对话接口，底层对接智能体架构（如 Lagraphn + DeepSeek + RAG 向量库）。当前后端已落地数据/阈值/指令/日志骨架；LLM 决策与对话接口为平台智能化层，由服务端统一封装对接底层模型，与前端契约保持一致。

## 7. 端到端数据流与灌溉控制闭环

```
[STM32 采集端] --4G/MQTT--> [OneNET] --REST(2s轮询)--> [服务端缓存]
                                                          │  │
  前端 SSE(2s/变化才推)+10s兜底 <----- GET /api/stream <──┘  │
  前端 控制/阈值  ──POST /api/command──> [服务端] --set-desired-property--> [OneNET]
                                                          │                      │
                                                  记录 DecisionLog        MQTT 下发
                                                          │                      ▼
                                                  前端实时呈现 <── F 状态回采 ── [STM32 继电器/水泵]
```

该闭环体现"**数据感知 → 智能分析 → 精准研判 → 科学决策 → 闭环管控**"的完整链路。

## 9. 后续演进

1. **时序数据平台**：接入 Kafka + InfluxDB，支撑多设备、海量历史数据的高并发写入与查询。
2. 后续将轻量级H2数据库升级为Mysql或Pgsql之类事务性更好的
3. **算法增强**：拓展病虫害预警、产量预估等功能。
4. **决策自动化**：在"手动决策"基础上，增加"基于阈值的自动化决策"并行支持。
5. **移动端独立化**：演进为独立 APP / 小程序，提升户外作业体验。
6. **多租户/多产区**：支持不同作物、不同产区的配置化接入。
